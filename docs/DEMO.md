# 作品演示视频脚本（约3分钟）

入口：`launch-fill.cmd`。使用虚构档案和已验证页面，录制前先完整演练。窗口每次只执行一轮，新增字段需要再次识别。

| 时间 | 画面 | 口播要点 |
| --- | --- | --- |
| 0:00—0:20 | 项目标题、空白表单 | 求职者在不同网申系统反复录入相同资料；本项目复用一份本地档案 |
| 0:20—0:40 | 控制窗口、示例档案 | 档案是事实来源，用户选择网页、档案及模式，手动完成登录 |
| 0:40—1:20 | 规则识别、核对计划、确认填写 | 展示字段映射、浏览器执行与实际值读回 |
| 1:20—2:00 | 切换模型辅助，重新识别并填写语义下拉 | 规则优先，本机 Ollama 辅助规则无法匹配的受支持类别选项；合法匹配直接填写。使用事先验证能触发模型的案例 |
| 2:00—2:25 | 缺失、已有内容和未支持项 | 缺失留空，已有值保留，不兼容或不确定的选项跳过，并说明原因 |
| 2:25—2:45 | 动态字段出现后再次识别，结果报告 | 新增字段需要用户重新识别，报告区分填写验证、缺失、跳过和失败 |
| 2:45—3:00 | 架构与仓库文档 | 观察→映射→校验→执行→读回；Skill约定行为边界，用户最终保存和投递 |

模型片段可配合当时的 `ollama ps`，证明实际处理器使用。剪辑等待时间时标注“等待过程已压缩”。规则填写片段不可标成模型推理。模型失败时如实说明，历史实录需标注日期和来源。

收尾口播：项目把网页操作与个人事实分离，通过规则和本地模型互补，让重复填写可核对、可追溯。后续将扩展站点组件适配和独立案例验证。

成片验收：填写前、操作过程、填写后和结果清晰可见；音频字幕可读；无密钥、登录信息或真实联系方式；实际入口与README一致；文件可播放，提交链接可访问。
