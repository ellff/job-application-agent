# 验证材料与录屏清单

验证材料就是效果证据：同一次运行的前后截图、终端结果和对应报告即可。

| 材料 | 获取方式 |
| --- | --- |
| 01-environment.png | 软件版本、ollama list；模型运行时另记录ollama ps |
| 02-before.png | 虚构资料、本地测试表单填写前 |
| 03-after.png | 同一表单填写后 |
| 04-result.png | 终端填写与验证汇总 |
| 05-exception.png | 缺失资料、已有内容或不兼容选项的结果 |

可公开图片放docs/images/。原始报告留artifacts/；确认脱敏后将需要的副本放docs/evidence/。不要直接公开整个日志目录。

## 操作顺序

1. 记录日期、命令、页面版本、模型及模式。
2. 执行 `.\scripts\start.ps1 -Test`，保存实际输出，失败如实记录。
3. 运行本地展示，拍填写前后与结果。默认规则模式应明确标注。
4. 若验证模型识别，配置云端密钥后运行 `.\scripts\start.ps1 -Model -Realistic`，关闭浏览器后运行 `node src/evaluate-realistic.cjs`，保存当次结果。
5. 验证本地模型时运行 `.\scripts\try-ollama.ps1 -Test`，保存输出与耗时。这只是选项匹配测试。
6. 需要完整模型异常实验时运行 `.\scripts\start.ps1 -Exceptions`；未运行则不写成当次成绩。

每组证据写清“何时、用什么模式、验证什么、结果是什么”。旧截图先确认来源，不能证明当前版本效果。

## 录屏

填写过程作为主体即可，建议前面用15秒说明项目解决的问题，中间展示空白表单、启动命令、实际模式、填写过程和验证结果，最后用15秒说明缺失留空、已有内容保留及人工核对。约2—4分钟，按实际速度剪辑。

如果声称本地模型驱动，需展示真实本地模型运行证据；规则入口不能标为大模型填写。使用虚构资料，避开密钥和登录信息。视频可兼作过程证据，报告仍保留关键前后对比。

## 窗口版验收补充

窗口入口为launch-fill.cmd。录制规则识别→核对计划→确认填写；若有难匹配下拉，切换规则＋本地模型辅助，重新识别，接受或跳过建议。展示换页后再次识别。窗口每次一轮，旧终端两轮说明不适用。新增tests/window.test.cjs验证按钮启用、模式变化后计划失效、单轮新增字段不自动补填、模型确认与旧页面计划保护；其中模型响应采用模拟，真实Ollama速度和准确性仍需实测。

窗口最新行为：模型辅助匹配合法下拉选项后直接填写，不再展示“接受建议/跳过”。录屏无需逐项确认；无法确定、非法结果或请求失败仍跳过。旧终端入口保持原确认逻辑。
