# 部署与运行

## 环境

Windows PowerShell、Node.js（建议22或更高版本）、npm；本地模型另需Ollama。记录实际OS、CPU、内存、GPU、显存和软件版本，不预设已启用GPU。

```powershell
node --version
npm install
npx playwright install chromium
.\scripts\start.ps1
.\scripts\start.ps1 -Test
```

默认入口为规则实验，无需模型密钥。测试中模拟接口结果不等于真实模型效果。

## 本地模型

安装并启动Ollama后：

```powershell
ollama pull qwen3:4b
ollama list
.\scripts\try-ollama.ps1 -Test
```

此测试仅检查类别候选匹配及耗时，不操作网页。实际页面运行：

```powershell
.\scripts\try-ollama.ps1 -Profile ".\.local\personal-profile.json"
```

先准备用户指定的JSON档案；字段参考项目映射。详细页面操作见根目录TRY-ZHAOPIN.md。用户手动登录并进入编辑状态，按回车识别，输入fill执行，再按提示进行第二轮；模型建议输入yes确认。不要用虚构资料正式投递。

适配固定访问127.0.0.1:11434的/api/chat，固定模型qwen3:4b，不自动下载、不回退云端。运行时用ollama ps记录实际处理器信息；有NVIDIA显卡时可记录nvidia-smi。模型存储和硬件调度由Ollama管理，CPU运行耗时需实测。

优化包括关闭思考、低温度、限制上下文和生成长度、JSON结构约束、180秒超时、规则先行及进程内确认缓存。没有进行权重微调；未做前后对照时不得声称提速比例。

## 云端语义实验

在本机环境变量配置SILICONFLOW_API_KEY，不写入仓库；默认模型Qwen/Qwen3.5-4B，可用SILICONFLOW_MODEL修改。

```powershell
.\scripts\start.ps1 -Model -Realistic
node src/evaluate-realistic.cjs
.\scripts\start.ps1 -Exceptions
```

关闭实验浏览器后再评测。结果位于artifacts/。云端字段识别实验和本地模型选项辅助须分开记录。

skills/job-application-fill/SKILL.md描述事实来源、字段语义、异常处理和验证。映射表提供标准键，脚本检查模型输出并执行。支持技能的Agent可明确读取项目Skill；真实页面规则入口并非所有决策都由模型读取Skill完成。

## 排错

缺少依赖时重新安装Playwright与浏览器。模型连接失败时检查Ollama服务、端口和模型列表。超时记录硬件及加载时间。控件未填写时查看报告原因，不将匹配数当成成功数。页面变化后重新识别，不同时启动两个复用登录会话的实例。

## 连续填写（新增）

真实页面入口现在一次启动可反复使用。运行 `.\scripts\try-zhaopin.ps1`（规则）或 `.\scripts\try-ollama.ps1`（本地模型选项辅助）。每轮完成后浏览器保持打开；手动保存并切换到下一页面或编辑模块，回终端按回车重新识别，再输入fill。多个标签页时按编号选择目标。输入q退出并关闭程序浏览器。取消填写或本轮出错后也可重新识别。不会自动点击下一步；新页面每次重新生成计划，原有内容继续保留。档案在启动时加载，修改档案后需重新启动。
也可双击根目录 launch-fill.cmd，打开控制窗口并选择填写模式。默认读取 .local/personal-profile.json；需提前准备档案，本地模型模式需启动Ollama。

## 本地控制窗口（推荐入口）

安装依赖后，双击launch-fill.cmd；或运行 `.\scripts\start-window.ps1`。控制界面在独立浏览器窗口中打开，后台仅监听本机随机端口，不需要在终端输入命令。网址与档案路径可在窗口填写，默认网址读取try-zhaopin.ps1，默认档案为.local/personal-profile.json。网址和路径在该控制窗口的本地存储中暂存，不保证跨启动保留；档案每次识别时重新读取。

操作顺序：打开网页→手动登录并进入编辑状态→选择目标标签页→选择模式→识别当前页→滚动核对计划→确认填写。规则模式不调用模型；辅助模式复用规则识别，并仅在下拉规则无法匹配时请求本地Ollama，合法匹配直接执行，不逐项确认。每次仅执行一轮，新增字段、剩余字段由用户再次识别，不自动第二轮。模式、档案或目标标签页变化后重新识别。刷新或跳转使旧计划失效，填过的计划不可再次执行。

模型最长等待180秒；无法确定或模型请求失败时跳过。执行期间不要操作目标表单。结果报告位于artifacts/window/。点击退出或关闭控制窗口会关闭程序的浏览器；先完成需要的人工核对与保存。旧终端脚本仍保持两轮逻辑，勿与窗口同时运行。窗口版不是浏览器扩展，只控制程序自己打开的浏览器。
地区与日期修复：窗口入口已取消封装时额外添加的统一跳过条件，直接复用已有地区级联与日历处理模块。支持的组件逐层选择并读回；出生日期要求完整YYYY-MM-DD，已有内容保留。无法识别组件或资料不完整时仍报告并跳过。更新后须退出旧窗口并重新启动。

窗口界面精简：档案路径收进“设置”；只有多个标签页时才展示选择框，列表自动更新。模型辅助填写在点击本轮“确认填写”后自动执行合法下拉匹配，不再弹出接受/跳过。每次识别只展示当前轮计划和结果，详细报告仍写入artifacts/window/。旧终端入口的模型确认流程保持不变。
电话组合控件：同一表单项中的一个区号下拉和一个可编辑号码框会分别识别；区号保持不变，号码框读取phone档案字段。已有号码保留；如果存在多个无法区分的号码框，仍跳过并交由人工处理。

## 教育经历与动态字段

默认虚构档案现投影到用户提供的硕士教育记录，旧档案已在.local/备份；不是根据截图生成博士经历。学位用academic_degree，学历沿用degree，两者分开。.local/education-bachelor-demo.json与.local/education-master-demo.json分别保存本科、硕士演示档案；在窗口“设置”的档案路径切换，每次切换后重新识别。院系、专业、课程为明确标注的虚构演示补充，不代表真实履历。缺失排名及海外年限留空，海外经历沿用“否”。

已增加入学时间、受教育类型、学位、年级排名、海外学习经历/年限、研究方向、院系、专业课程映射。下拉辅助模式支持上述类别选项的等价匹配。原生月份与已适配只读月份面板支持入学年月；组件不兼容时报告跳过，不补造入学日。学历选择后出现的新字段仍须再次点“识别当前页”再填写，不自动点击添加或保存，不自动建立多条教育记录。

教育日期约定（用户明确授权）：窗口中入学、毕业时间只有YYYY-MM时，原生月份或已适配月份面板仍填年月；控件要求具体日期时按当月1日填写，结果与报告注明按约定补日。出生日期不适用，仍需完整年月日。日历中隐藏的月份表不再被当成当前可见月份面板。
