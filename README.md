# Job Application Agent：招聘表单辅助填写智能体

本项目面向求职过程中重复录入个人资料的场景，将标准档案、字段识别、浏览器执行与结果验证连接起来。用户准备 JSON 档案，打开测试表单或指定招聘页面，程序读取可见字段，将字段映射到标准键，从档案中提取已有事实，执行填写并读回验证。作品定位为可复现的智能体实践，不替代用户核对，也不自动投递。

## 特点与核心亮点

项目通过标准键将网页字段与个人资料解耦，不仅依赖固定页面顺序。本地实验支持模型根据标签与上下文输出映射；真实页面采用规则先行、模型辅助第二轮类别选项的方案。前者验证语义识别，后者强调稳定执行，两种流程分别记录效果。模型不会被当成个人事实来源：缺失资料留空，歧义字段跳过，已有内容保留，下拉框根据真实候选处理。窗口中模型合法匹配直接执行；终端模式保留建议确认，填写完成再次读取控件，分别统计匹配数、填写数与验证结果。

## 架构与技术实现

流程为：页面观察 → 规则或模型映射 → 输出校验 → 档案取值 → 浏览器填写 → 读回验证 → 人工核对。

观察层使用 Playwright 读取标签、控件类型、区域与选项。决策层通过标准字段映射及模型语义判断生成计划。执行层检查定位与页面状态，再从本地档案读取事实。验证层读取实际控件值，报告缺失、歧义、不支持与验证失败。Skill 提供语义判断和行为边界，脚本负责浏览器操作与确定性校验；项目中的 Skill 文件并不等于已安装到个人技能目录。

窗口版每次只执行一轮，由用户手动再次识别；旧终端入口仍保留两轮补扫。窗口入口已恢复调用已有地区级联与日历模块；只有已适配组件可填写，实际网站效果需验证。iframe、重复教育记录及不同站点组件仍有局限。

## 本地算力与优化

浏览器控制、档案读取和校验在本机运行。本地模型通过 Ollama 调用 qwen3:4b，用于真实页面第二轮选项辅助，不代表整个字段识别流程都在本地模型中运行。采用 temperature=0、num_ctx=4096、num_predict=512、think=false、结构化 JSON、合法键检查及180秒超时。规则先行减少调用，确认缓存减少重复判断，执行前复查避免使用过期选项。项目未进行权重微调、训练或自行量化；实际 GPU 使用、显存与耗时需在部署机测量。

## 实际技术栈

- Node.js、CommonJS、PowerShell、Playwright、JSON 与 Markdown Skill。
- 本地适配：Ollama / qwen3:4b。
- 云端适配：SiliconFlow，默认 Qwen/Qwen3.5-4B；另有 OpenAI 和集团接口适配，真实运行效果分别验证。

## 启动

推荐双击 `launch-fill.cmd` 打开本地控制窗口。在窗口填写网址与档案路径，选择“规则填写”或“模型辅助填写”，打开网页并手动登录，点击“识别当前页”，滚动核对计划后点击“确认填写”。模型合法匹配直接填写，不逐项询问。窗口每次只执行一轮，不自动补扫；手动换页或切换模式后重新识别。界面由本机服务提供，不是浏览器扩展；辅助模式将所需类别值与候选发送给本机Ollama。首次启动前仍须安装下列依赖。不要同时启动旧终端入口与窗口，它们复用同一登录目录。

Windows PowerShell，在项目目录运行：

```powershell
npm install
npx playwright install chromium
.\start.ps1
```

默认是本地规则实验。历史记录中的模型新表达表单15/15、异常场景3/3不代表当前版本已重新通过；交付前按验证清单重跑。模拟接口测试不证明真实模型准确率，本地测试通过也不证明所有招聘网站兼容。


## 首次准备个人档案

仓库中的 profile.json 是虚构示例，不用于正式投递。窗口默认读取 .local/personal-profile.json，先执行：

```powershell
New-Item -ItemType Directory -Force .local
Copy-Item profile.json .local/personal-profile.json
```

再在本机编辑该文件，填写自己的真实资料；不要将该文件上传。也可以在窗口设置中指定其他档案路径。
